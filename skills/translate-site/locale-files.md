# Translating Rosey locale JSON files

Part 1 of two. Fills in untranslated and stale entries in `rosey/locales/{code}.json` — shared UI plus any page text tagged with `data-rosey`. Read [`SKILL.md`](SKILL.md) first to confirm which part applies.

**Most sites need only this file.** Reach for [content-directories.md](content-directories.md) only if the project has per-locale content directories.

## Prerequisites

- Locale files exist at `rosey/locales/{code}.json` (generated by `write-locales`).
- The user has said which locale(s) to translate and into which language(s).
- `base.json` is up to date — run `npx rosey generate` + `npx rosey-cloudcannon-connector write-locales` if unsure.
- **Source-language copy edits are finished.** Changing source text after translating marks every translation of it out of date — correct behaviour, but pure churn. Settle the English copy first, in both directions.

## Locale file format

Each file is a flat JSON object keyed by Rosey translation keys:

```json
{
  "hero:title": {
    "original": "Welcome to Sendit",
    "value": "Welcome to Sendit",
    "_base_original": "Welcome to Sendit"
  },
  "hero:subtitle": {
    "original": "The best email platform",
    "value": "La meilleure plateforme email",
    "_base_original": "The best email platform"
  }
}
```

| Field            | Description                                                                 |
| ---------------- | --------------------------------------------------------------------------- |
| `original`       | Source text when the translation was last acknowledged                      |
| `value`          | The translation (or the source original if untranslated)                    |
| `_base_original` | Current source text from `base.json`, updated by `write-locales` each build |

Classification follows from these three fields:

- **Untranslated** — `value === original` and `original === _base_original`. Needs full translation.
- **Stale** — `original !== _base_original`. Source changed since the translation was acknowledged. Translate from `_base_original`, then set `original = _base_original`.
- **Current** — `original === _base_original` and `value !== original`. Already translated; leave it alone.

## Workflow overview

This skill ships helper scripts that do the mechanical work (classification, translation memory, merging, HTML validation), leaving only the actual translation to the AI. Three phases:

1. **Prepare** — a script classifies entries and writes a slim task file.
2. **Translate** — the AI reads the task file and fills in translations.
3. **Merge** — a script merges translations back into the full locale file.

**Locate the scripts before running them.** The commands below assume the skills were copied to `skills/` in the project root. Depending on the install route they may be under `.agents/skills/`, `.cursor/skills/`, or a plugin directory outside the project — adjust the path to wherever this skill's `scripts/` sits. If they aren't present at all, use the **Manual Fallback** at the end of Part 1.

## Phase 1.1: Prepare

```bash
node skills/translate-site/scripts/prepare-translation.mjs --locale fr
```

The script:

- Classifies every entry as untranslated / stale / current (skip)
- Builds a **translation memory** from already-translated entries and auto-applies exact matches (e.g. "Recent Posts" appearing 4×, translated once, applied everywhere) — writing those straight back to the locale file
- Picks tone/register examples from existing translations
- Writes a slim task file to `rosey/locales/.translation-task-{code}.json`
- Reports counts (total, auto-applied, needs AI, stale)

Flags: `--locale <code>` (required), `--source <dir>` (default `rosey`), `--output <path>`, `--examples <n>` (default 5).

## Phase 1.2: Translate

Read the task file. It contains:

- `_meta.tone_examples` — already-translated entries showing the project's tone/register. Match this style.
- `untranslated` — entries needing full translation. Each has `original`; add a `value`.
- `stale` — entries where the source changed. Each has `old_original`, `new_original`, `old_value`; add a `value` based on `new_original`.

#### Translation rules

**Use key namespaces for context.** `nav:about` = an About nav link; `index:hero:title` = a hero page title; `footer:copyright` = footer copyright. For short/ambiguous strings ("More", "Back", "Home") the namespace tells you how it should read.

**Preserve HTML structure.** Locale values are **always HTML** (the SSG converted Markdown to HTML at build time). Keep every tag, attribute, and nesting; translate only the text nodes.

```json
{
  "original": "<p>A starting point for <strong>developers</strong> looking to build a website.</p>",
  "value": "<p>Un point de départ pour les <strong>développeurs</strong> cherchant à créer un site web.</p>"
}
```

- Keep all tags in place (`<p>`, `<strong>`, `<a href="...">`, `<br>`).
- Preserve attributes exactly (especially `href`, `class`, `id`).
- Keep `&nbsp;` and other entities where they appear.

**Translate in namespace-grouped batches**, not one entry at a time in isolation — group all `nav:*` together, all `index:hero:*` together, etc. This gives natural context and consistent results.

**Match tone and register** using `_meta.tone_examples`: formal vs informal address (vous/tu, Sie/du, usted/tú), and terminology consistency (if "Sign up" is already "S'inscrire", don't switch to "Créer un compte").

**Intentional non-translations.** Brand names ("CloudCannon"), product names ("Rosey"), proper nouns, technical terms, URLs, email addresses, and code snippets stay identical — set `value` equal to `original`. Signals: the key contains `brand`/`name`/`logo`/`copyright`, or the value is a single proper noun/trademark/URL/code. When in doubt, translate — a reviewer can revert one entry more easily than spot a missing translation.

**Whitespace.** `write-locales` preserves whitespace from the HTML (entries may be `" Blog "`). Preserve the same leading/trailing whitespace — Rosey substitutes the value directly into HTML and altered whitespace can break rendering.

After translating, write the task file back to the same path with `value` fields added.

## Phase 1.3: Merge

```bash
node skills/translate-site/scripts/merge-translation.mjs --locale fr
```

The script:

- Merges `value` fields from the task file into the full locale file
- For stale entries, sets `original = _base_original` (clears the stale flag)
- **Validates HTML** — checks tag names/counts match and `<a>` href values are preserved; logs warnings for mismatches but still writes
- Sorts keys alphabetically, 2-space indent, trailing newline
- Deletes the task file after a successful merge

Flags: `--locale <code>` (required), `--source <dir>` (default `rosey`), `--input <path>`, `--dry-run`.

If the script reports HTML warnings, review those entries and fix broken tags before committing.

## Part 1 checklist

- [ ] Run `prepare-translation.mjs`; review the counts
- [ ] Read the task file; check tone examples
- [ ] Translate all `untranslated` entries (add `value`)
- [ ] Translate all `stale` entries (add `value` based on `new_original`)
- [ ] Preserve HTML tags, attributes, whitespace
- [ ] Match tone/register
- [ ] Write the task file back; run `merge-translation.mjs`; check warnings
- [ ] Review the `git diff` of the locale file

## Manual fallback (Part 1)

If the helper scripts aren't available, the AI reads and writes the full locale file directly:

1. **Classify** every entry as untranslated / stale / current using the three-field rules above. Report counts (e.g. "42 untranslated, 3 stale, 107 current — translating 45 entries to French").
2. **Translate** applying the same rules as Phase 1.2. Match tone/register of existing translations; translate in namespace-grouped batches. For stale entries, set both `value` (new translation) and `original = _base_original`.
3. **Write back:**
   - `JSON.stringify(data, null, 2)` (2-space indent), keys sorted alphabetically (matching `write-locales` output)
   - Preserve all three fields on every entry — never drop `_base_original`
   - Don't add or remove keys — only modify `value` (and `original` for stale entries)
   - End with a trailing newline
